## 一、它到底是什么（一句话）

**它把「模型说要做什么」变成「代码真的去做」，然后检查模型有没有撒谎。**

不是 agent 框架，是一个**执行外骨骼**：模型是脑，它是手和眼睛。

## 四、三处最值得看的地方

### ① 工具标记 → 真执行（L201 `do_tool`）

```python
if tag == "读":   白名单校验 → 读文件 → 截断 1500 → 回灌
if tag == "查":   查索引 → 只给命中的文件名 + 摘要 → 记进 RUN_HITS
if tag == "记":   POST 到外部库（只写，不查）
```

**这是神经与符号的接口。** 模型只需说 `[读:xxx]`，不需要会读文件。

### ② 接地守卫（L360 `grounding_violations`）

它抓的是这种错：

```
检索命中：《会议记录.md》
模型回答：账本里有音色，在会议记录.md 中提到   ← 把 A 的内容算到 B 头上
```

判据：回答里提到的文件名，必须在 `RUN_HITS` 里；任务点名的对象，若模型断言肯定存在，也必须在命中集里。

**这是 CE 唯一无法用"模型变强"替代的部分。**

### ③ 分解循环（L410 `run_task`）

```
拆步骤（模型自己拆，代码只催）→ 模型输出 → 提标记 → 执行 → 回灌 → 再问
最多 3 轮，第 3 轮不再给工具，强制收敛
```

## 五、你那个判断（"它的核心作用是分解器"）—— 要分开看

**同意的一半**：多步任务上，代码确实在扮演"分解者 + 催促者"，把
"查完再说"这件事从模型自觉变成流程强制。

**要标"未验证"的一半**：这个价值会不会随着模型变大而消失？

```
小模型（7B–14B）  不会自己拆，也不会主动用工具 → 分解器有用（已验证 4/4）
中大型模型        自己就会拆、会主动调工具     → 分解器可能反而干扰
                  （它的模板比模型自己的推理差）
```

**我现在的判断是分层的，而且可被证伪：**

| 机制 | 小模型 | 大模型 |
|---|---|---|
| 分解 / 催促 | 有用 | **会贬值**（可能变干扰） |
| 工具执行 | 有用 | 有用（但大模型自己也能调） |
| 接地守卫 | 有用 | **仍然有用**（防把 A 算到 B） |
| 声称监控 | 有用 | 有用（省得它编"已做了"） |

**可检验的做法**：同一个多步任务，分别在
（a）裸 9B、（b）CE + 9B 上跑，比成功率。
要做大模型那一栏，得有一台能跑 30B 以上的机器——**现在没有，所以那一格写"未验证"，不许拍板。**
