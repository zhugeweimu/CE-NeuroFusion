# CE · 执行外骨骼

> 「拒绝臃肿框架，用代码给大模型戴上紧箍咒。」

> **环境要求：Python 3.9+**
> **本项目不含大模型。** 你要自己起一个 OpenAI 兼容的本地模型服务
> （llama.cpp / Ollama / LM Studio / vLLM 都行，默认地址 `http://127.0.0.1:8080/v1/chat/completions`）。
> 没起模型时 CE 能启动、`/health` 正常，但一发起任务就会返回
> 「连不上模型服务」并给出三步排查——不会崩。

CE 是一个**单文件、纯标准库、零依赖**的本地执行器（HTTP 服务，约 2701 行 Python）。
它不训练模型、不做 RAG 平台、也不试图取代 Agent 框架——它只做一件事：

**把大活拆成小模型咽得下的小步，替它取原料，盯它别乱说，每步留档，能回滚。**

```
你：归拢这堆文档，写份日报
CE：拆成几块 → 每块自己回原文取料 → 逐块产出 → 合并 → 落盘 + 留检查点
```

> 设计隐喻：规划（拆步）/ 留档（笔记与事实清单）/ 反射（熔断与守卫）。
> **这是隐喻，不是仿生学依据**——CE 里没有任何神经元模型，全是 if 和文件。

## 一、为什么需要它：本地小模型的六种水土不服

多数 Agent 框架默认"上下文很宽、模型很听话"。本地跑 8B/9B 时你会遇到：

| 症状 | 真实表现 |
|---|---|
| **上下文爆炸** | 聊几轮就超长；超了不一定报错，而是**静默截断**，模型开始"金鱼记忆" |
| **严重幻觉** | 没查文件说查了；把 A 文件的内容硬安到 B 头上 |
| **落不了地** | 输出一大段，还得手动复制进笔记软件 |
| **没有习惯** | 每次重复发同样的背景，它记不住你的偏好 |
| **长任务断层** | 步骤一多就飘，最后产出一堆半好半坏的废料 |
| **死循环** | 找不到工具就无限重试，烧时间也卡进程 |

## 二、CE 的解法：不信任"自觉"，把可靠性写进代码

| 解法 | 是什么 | 属谁 | 验证情况 |
|---|---|---|---|
| 🔪 **压榨与分段喂养** | `tools/probe.py` 测上下文/槽数/显存/字-token比 → 算出单请求能喂多少字；超了按段切，段内提炼、最后合并 | **CE 本体** | ✅ 8K 上下文实测单请求约 8900 字 |
| 🛡️ **接地守卫** | 回答里的文件名/路径必须在本轮真实取料里；每块与单轮不合格**拦下重写**；最终成品不合格**保留原文 + 加一行警告**（不把内容换成空话） | **CE 本体** | ✅ 拦下过编造文件名；⚠️ 缩写名（`笔记A.md`→`A.md`）会误报，只警告 |
| 🔢 **数字守卫** | 同一个量在不同步骤给出不同值 → 标红（如 `代码类共项=14/17`） | **CE 本体** | ✅ 实测抓到 17/15/14 漂移 |
| 🔄 **断点续传与回滚** | 每步落 `step-NN.json`；`/rollback` 截到第 N 步、清过期素材、**用补充要求重拆剩余块**，再跑就接着走 | **CE 本体** | ✅ 端到端跑通（6 块 → 回滚 → 续跑完） |
| 🛑 **预算与熔断** | `budget_sec/budget_calls` 超限如实说"没做完"；同一动作第 4 次直接停手 | **CE 本体** | ✅ 双向验证过 |
| 🧠 **笔记库联动** | 内置 `[搜笔:] [读笔:] [日:] [记:xx.md|内容]`，直接读写 Obsidian 库；只追加不覆盖、原子写、库自动发现 | **CE 本体** | ✅ 实测 4 个库自动识别、跨库检索 |

**边界说清：**

```
CE 本体：编排、取料、守卫、分段、回滚、预算、笔记库标记。
```

## 三、快速开始（三步，别抄错文件名）

```bash
# 1) 先起模型服务（CE 不带模型）。三种常见做法：
#    llama.cpp:  llama-server -m 模型.gguf -c 8192 --port 8080
#    Ollama:     ollama serve            # 然后把 llama_url 改成 :11434/v1/chat/completions
#    LM Studio:  打开 Local Server，端口默认 1234
#    验证：curl http://127.0.0.1:8080/v1/models  能返回模型列表才算起好
#
#    qwen3 需要关思考，否则 content 是空的；
#    别的服务不认这个字段时，CE 会自动去掉重试（日志会写明）

# 2) 配置
cd ce
cp config.example.json config.json
#    至少改三处：read_roots（能读哪些目录）、llama_url、model

# 3) 自检硬件 → 启动
python tools/probe.py        # 生成 capacity.json（单请求字数、能否并行）
python ce_tool.py            # 默认 http://127.0.0.1:8092
```

> ⚠️ 入口是 **`ce_tool.py`**，不是 `ce.py`。写错文件名是新人第一坑。

跑一个任务：

```bash
curl -X POST http://127.0.0.1:8092/task \
  -H 'Content-Type: application/json' \
  -d '{"task":"归拢 ~/notes 最近一天改过的文件，写份简报","session_id":"demo","stepwise":true}'
```

返回里带 `progress: {step, of, done, next}`。

**两种跑法：**

```
{"...","stepwise":true,"auto":true}   一次请求里把所有块跑完，直接给成品（用户视角就是一轮）
{"...","stepwise":true}               一次只跑一块，没做完再叫一次同 session
```

`auto` 受 `budget_sec`（默认 180 秒）约束。实测：一句复杂指令 → 6 块 → 12.7 秒 → 一次返回成品。

常用接口：

```
POST /task        跑一步，或一次跑完（auto:true）
GET  /runs?session=demo          看每步检查点（含 flags 标红）
GET  /logs?session=demo&tail=50  人可直读的运行日志
GET  /last?session=demo          取回已有产出（超时/断线后用）
POST /rollback    回滚：{"session_id":"demo","to_step":2,"extra":"只算代码文件"}
```

## 五、包里每个文件干什么

| 文件 | 作用 |

## 六、验证范围

**验证过的环境：**

```

上下文    8192（槽数 1）
硬件      RTX 2070S 8G / Windows 10
实测      18KB 文档 → 6 块 → 3381 字成品，约 60 秒
流程      启动（模型通/不通）、分段、回滚、守卫拦截、并发隔离
```

```
其他模型（7B/14B/32B）、其他量化、Linux/macOS、多卡、
上下文 >32K 的并行场景、真人长期使用
```

## 九、先把话说在前面（免责与预期管理）

**CE 不会让模型变聪明。** 它只是给模型套上一副外骨骼：把活拆小、把料备好、把谎话抓住、把每一步留档。
模型本身的水平，一点没变。

### 它一定会让你失望的地方

`
· 同一个指令，两次结果可能不一样（小模型有随机性）
· 长任务跑到后面会忘掉前面（8K 上下文尤其明显，CE 只能靠分块缓解，不能消除）
· 会编数字、编文件名、编“我已经查过了”（守卫能抓一部分，抓不到“理解错”）
· 让它“随便写点”“帮我优化一下”，大概率给你一堆正确但没用的废话
`

**最后一条不是 bug，是模型的本质。** 缺具体对象和交付物的指令，任何执行器都救不了。
见 [docs/12-怎么下指令.md](docs/12-怎么下指令.md)——那里写了怎么问它才靠谱。

### 不要用它做的四类事

`
✗ 不可逆操作      删库、格式化、批量改文件（它可能改错，且改错难还原）
✗ 钱和合同        下单、付款、签协议、对外发邮件
✗ 专业判断        医疗、法律、投资、安全审计的最终结论
✗ 无人值守的关键流程  它跑飞了没人接，损失算谁的
`

**它能干的，是“有明确验收标准、错了能看出来”的活**：整理、分类、统计、改写、提取、比对。

### 期望值

`
把它当实习生：能给方向、能给料、能验收 → 它很有用
把它当专家：只给一句话，等它惊艳你 → 它一定让你失望
`

## 十、它不做什么

- 不承诺「意识」「情感」。
- 不做通用 agent 框架，不接管你的编排。
- 不自动判断「哪一步错了」：检查点和标红只给线索，**回滚由人决定**。
- 不保证拦截所有幻觉：能拦"编文件名/编数字"，拦不住"理解错"。
