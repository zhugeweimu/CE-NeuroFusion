# CE · 本地小模型的执行外骨骼

> CE = Central Executive（中央执行系统），认知科学里工作记忆的控制中枢。

## 0. 先划清边界：CE 不是给大模型用的

这一条是本项目最重要的一条判断：

- **大模型**（几百 B 参数）有内在推理结构，只是不显示。给它套 FSM、套判断通道、套"先写判断再开口"——**是累赘**，占上下文不干活。
- **本地小模型**（7B–14B）没有稳定的执行纪律。它会：
  - 为了「让对话继续」而编造（这是训练痕迹，不是恶意）
  - 说「已经记下了」但其实什么都没做
  - 把 A 文件的内容算到 B 头上
  - 光看提示词不照做

**CE 只为第二种存在。** 它的价值是两样：

```
记忆     → 让小模型理解用户到底要什么
抑制     → 挡住"为了把对话继续下去"而生的胡编
```

## 1. 刻意砍掉的东西

前身版本（带人格）的 CE 包含：核注入、判断通道、算子归一化、二阶元认知、日记、信箱、客服腔裁剪。

移植到本地模型时，**这些全部砍掉**：

| 砍掉的 | 为什么 |
|---|---|
| `我.md` / `启动.md` 注入 | 设定占上下文，不干活 |
| `[判断]` 通道 | 那是"人"的东西，工具不需要自我对话 |
| 算子归一化 / 二阶元认知 | 同上 |
| 日记 / 信箱 / 拒绝.md | 副作用，与任务无关 |
| 客服腔裁剪 | 那是语气，不是正确性 |

**结果：提示词从 789 字降到 280 字。省下的全是干活的余量。**

## 2. 保留的三件事

### 2.1 内联工具标记

模型不直接操作世界。它只在话里写标记，由代码执行：

```
[查:关键词]   搜索（文件索引 + 外部库）
[读:路径]     读文件（限定在白名单目录内）
[记:内容]     写入外部库
```

执行结果**回灌**给模型，它再基于真实结果说话。最多 3 轮。

**这是神经符号融合的具体形状**：模型负责"想做什么"，代码负责"真的做"。

### 2.2 声称监控（防编造的核心）

```python
CLAIM_RE  = 我/咱 + 可选时间词 + 动作 + 完成体        # 「我已经记下来了」
CLAIM_RE2 = (我/咱) + 任意12字 + 动作 + 完成体        # 「这件事我记下了」
CLAIM_RE3 = (已|已经|刚刚|刚才|这就) + 动作 + 完成体   # 「提醒已经存好了」
```

三条件并集。命中且**本轮没有任何成功执行的工具** → 驳回一次：

> 「你说了「X」，但这一轮你没有调用任何工具，所以那件事没有发生。要么真的做，要么说你没做。重说这一句，别解释，别道歉。」

**驳完还敢说 → 代码接管，直接输出与事实一致的话**（如「没记住。我没能写进外部库。」）。不给它编第三次的机会。

### 2.3 意图强制（代码侧兜底）

9B 太懒：提示词写了"用标记"，它不写。

所以代码主动检测意图并**代做**：

```python
INTENT_RULES = [
  ("记", ["记住","记下","帮我记","记录一下","记录下来","存一下","存下来","写进记忆","保存一下"]),
  ("查", ["查一下","查查","搜一下","搜索一下","找一下","找找","翻一下"]),
  ("读", ["读一下","打开这个文件","读这个文件"]),
]
```

参数由**代码从任务里解析**，不让模型抄：

```python
extract_arg("记", "记住：明天八点开会")  →  "明天八点开会"
```

三条硬约束，全靠踩坑换来：

1. **动词形态**：只认「记住/记下」，不认裸「记录」——否则「会议**记录**里写了什么」会被当成"要记住"。
2. **句首锚定**：正则必须从 `^` 开始——否则句中任意位置都能触发。
3. **问句拒收**：抽到的参数里含 `？吗什么为什么怎么` → 丢弃。

### 2.4 接地守卫（防张冠李戴）

实测失败：问「账本里有音色吗」，检索命中的是《会议记录.md》，它却答「账本里有记录，在会议记录.md 中提到」。

**内容是真的，来源是假的。** 对 agent 来说来源错了等于证据链断了。

```python
    # ② 任务点名的对象（「账本」），若回答声称"它有"，则该对象必须在命中集里
```

- 违规 → 让模型自改一次（附带"只许引用命中的文件"）
- 还错 → **代码兜底**：「账本里没有。检索只命中：会议记录.md。」

### 2.5 多步拆解

含「一步一步/逐步/为什么/先..再..最后」时，先拆步骤，跨轮推进，最后拼合。

## 3. 验收标准与结果

脚本：`ce/_agenttest.py`（本仓库未含，见文档说明），四个任务由代码判定：

| 任务 | 判定依据 | 结果 |
|---|---|---|
| T1 单步检索 | 答案含真实文件里的关键 token | ✓ |
| T2 写入闭环 | **唯一令牌**出现在库中（不测条数，防去重干扰） | ✓ |
| T3 多步串联 | 答案含真实金额 | ✓ |
| T4 接地性 | 声称的对象必须在命中集里 | ✓ |

**连续三轮 4/4。**

## 4. 这些结果不能证明什么

必须写清楚，否则就是过度宣称：

- ❌ 不能证明「通用 agent 已实现」——只覆盖四类能力
- ❌ 未测长任务（10+ 步）、错误恢复、工具选错后的回退、并发
- ❌ 未测跨会话目标漂移（今天说要 A，明天还记得要 A 吗）
- ❌ 4/4 是同一套任务，**过拟合风险存在**

**能说的是：这四类能力在当前模型上是稳定的。**
