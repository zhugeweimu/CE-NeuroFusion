# 15 · 自动迭代（增量取料）

> 一句话：**给一句"整理新增的东西"，它自己去翻新文件，边整理边找下一批。**

## 什么时候用

```
每天/每周想把手头新写的东西汇总一次
材料分散在很多文件里，单次塞不下
不想每次手动列出文件
```

## 怎么用

```json
POST /task
{
  "task": "把这些新增笔记整理成一份要点清单，每条一行",
  "session_id": "daily",
  "iterate": true,
  "max_rounds": 3,
  "save_to": "日报/2026-10-25.md"
}
```

| 字段 | 说明 |
|---|---|
| `iterate` | 开增量模式，其余字段照旧 |
| `max_rounds` | 最多循环几轮（默认 3）。每轮结束会**重新扫一次新文件** |
| `since` | 可选。不填就用上次跑到的时间（存在 `ce/.ce_iterate.json`）；首次默认近 7 天 |
| `save_to` | 可选，结果写文件（必须在 `write_roots` 内） |

## 它内部做了什么

```
① 记下游标 since（上次处理到哪个时间点）
② 扫 read_roots 下 mtime 比游标新的文件（.md/.txt/.json/.py/.log/.csv）
     跳过隐藏文件、index_skip_dirs、以及迭代状态文件自己
③ 按 source_chars 预算切批（单个文件超预算就截断并注明）
④ 每批：只带这一批的材料 + 你的任务 → 模型整理 → 落盘检查点
⑤ 一批做完后**再扫一次**：整理期间新掉进来的文件，进入下一轮
⑥ 汇总所有批次 → 更新游标 → 返回
```

**关键点：不用你列文件，也不会重复处理。** 游标是原子写的，断电不会写坏。

## 返回

```json
{"ok": true, "answer": "...", "files": 7, "batches": 3, "rounds": 2, "since": 1792860000.0}
```

| 字段 | 含义 |
|---|---|
| `files` | 这次实际处理了几个文件 |
| `batches` | 分了几批（模型调用次数 ≈ 批数） |
| `rounds` | 循环了几轮（>1 说明整理期间又有新文件进来） |
| `since` | 新游标，下次从这里继续 |

## 与 map-reduce 的区别

| | map-reduce | 自动迭代 |
|---|---|---|
| 材料来源 | 你给（source）或它现场取（[归:][读:]） | **按时间增量扫** |
| 是否跨请求 | 一次任务内 | **跨天/跨次，游标记忆** |
| 新文件 | 不管 | **边做边扫，自动捡新的** |
| 适合 | 一次性长文整理 | 日常增量汇总 |

## 限制（必须知道）

```
① 只按 mtime 判断"新"：文件被"复制但不改时间"可能漏掉
② 只读扩展名白名单：图片/PDF/Office 不在内（需先转文本）
③ 单批超预算会截断：超大文件要么先 [读:] 分段，要么单独处理
④ 不做跨批全局推理：每批独立整理，最后只是拼接
⑤ 游标是本机的：换机器/换目录会重新扫最近 7 天
```

## 和回滚配合

```
batch 产出不满意 → /rollback {session_id, to_step=<批号>} → 改提示词 → 重跑
游标不会因为回滚而倒退（避免重复烧钱），要重扫就显式传 since
```
