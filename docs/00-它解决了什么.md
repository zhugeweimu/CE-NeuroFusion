# 00 · 它到底解决了什么（先读这篇）

三个真问题，三套代码机制。**不是提示词技巧，是拦得住的东西。**

---

## 一、幻觉：让它想编也编不出来

### 问题在哪

小模型编造的不是"整段胡说"，而是**细节**：

```
"这 32 个文件里，代码类 17 个"        ← 数字可能是编的
"参考 docs\缺口清单.md 第 3 节"        ← 文件可能不存在
"上次我们说过要这样做"                 ← 记忆可能没有
```

这种错**最危险**：看起来完全合理，人不会去数。

### 四道机制（全在代码里，模型绕不过）

**① 真取料，不靠它回忆**

模型写 `[查:关键词]` / `[读:路径]` / `[归:目录@1]`，CE **真的去查**，把结果回灌。
它没有"凭记忆说"的机会——要么有料，要么说没有。

```
[归:C:\...\agent-neurofusion@1] → 真实返回 32 个文件
回答里说"共 32 个"                         ✔ 有据
```

**② 接地守卫：说了不存在的，拦下重写**

回答里出现的每个文件名/路径，必须在本轮**真实命中集**里。
命中集只增不减（同一轮里多次检索累加，不会被后来的结果覆盖）。

```
命中集：{ce_tool.py, deploy.py, README.md}
回答里写 "会议记录.md" → 不在命中集 → 拦下，要求重写
```

踩过的坑也写进代码了：模型爱在中文和英文之间插空格（`08-CE 缺口.md`），
所以比对前先归一化（去空格/连字符/点），否则会误判。

**③ 数字守卫：同一个量，前后必须一致**

```
步2：代码类共 17 个
步3：代码类共 14 个      ← 标红：代码类共项=14/17
```

按「量名」比而不是按单位比（`32 个文件` 和 `17 个文件` 单位相同但不是同一个量）。
最终答案里 ≥10 的数字若查不到出处，日志里提示（不拦，因为派生数字本来没出处）。

**④ 工具优先：能算的不用它想**

日期、文件数、目录清单、笔记路径——全部由代码取。
模型只负责"读懂"和"组织语言"。

### 边界（不吹）

```
✅ 能拦：编文件名、编路径、数字前后矛盾、无据的性格自述
⚠️ 会误报：模型写缩写（把「笔记 A.md」写成「A.md」）时可能判成无据——
   这时的处理是**保留原文 + 末尾加一行警告**，不会把内容换掉
❌ 拦不住：它把真实材料理解错、或者算错（那是能力问题）
❌ 拦不住：源头本身是错的（垃圾进，垃圾出）
```

## 二、压榨性能：8K 上下文干 32K 的活

### 核心思想

**不加大上下文，把活切小。** 一次只让它咽一口。

### 四步流水

```
① 拆要求      把"用户要什么"拆成几块彼此独立的交付物
              （不是拆成"先扫描再分类"这种动作链——那会退化成串行咀嚼）

② 取原料      每块开始前，代码先替它把原料取好（[归:] [读:] [查:]）
              首次取到的事实清单固化在链里，后面每块共用同一份

③ 分块产出    每块上下文 = 任务 + 共享素材 + 仅这一块的要求
              块与块之间互不依赖，都基于同一份原文

④ 合并        多块按标题拼接（零损耗）；最后一步直接出成品，不再"摘要的摘要"
```

**关键区别：**

```
❌ 串行咀嚼（早期做错的）：步1摘要喂步2 → 步2摘要喂步3 → …
                          每过一手衰减一层，合起来必然是"摘要的摘要"

✅ 现在：原文是共享底座，每块各自去吃 → 各自出成品片段 → 合并
        信息只衰减一次（块的粒度），不随步数累积
```

### 长文怎么处理

```
单请求能喂多少 = f(你的设备)
  n_ctx 8192 - 预留 1200 tokens，按 1.51 字/token，再打 85 折 → 约 8900 字
```

超过就**按段落切**，每段各自提炼，最后合并同一块的结果。
`tools/probe.py` 测出你这个数，写进 `capacity.json`；没测过就用保守预设 3000 字。

### 并行：能并行才并行

```
能并行 → 几块同时跑（快）
不能   → 一块一块跑（慢，但结果一样）
```

判定依据是自检结果（槽数 + 显存余量），不是拍脑袋。
**串行不丢人——本地模型不要钱，一轮里干完就行。**

### 实测

```
输入：18 KB 文档 + 一句要求
拆成：6 块（章节定位 / 概念提取 ×2 / 对比 / 原文佐证 / 综合）
产出：3381 字成品，每块 400–1000 字
耗时：约 60 秒（9B Q4，RTX 2070S，串行）
```

## 三、回滚：错了不用重来

### 为什么必须有

多步任务做到第 4 步发现第 2 步歪了——没有回滚就只能从头再来，
而**上下文、时间、模型情绪都耗不起**。

### 机制

**① 每一步都落检查点**

```
.ce_runs\<会话>\step-00.json … step-05.json
每份含：步骤原文 / 这一步的结论 / 工具产出摘要 / 标红信号 / 耗时
```

**② 标红信号（线索，不是判决）**

```
空产出      这一步没产出有效内容
重复熔断    同一步反复试同一动作
检索空手    要查的没查到
数字不一致  同一个量前后不同（代码类共项=14/17）
```

**③ 人决定回滚到哪**

```bash
POST /rollback
{"session_id":"demo","to_step":2,"extra":"只算代码文件，不要文档"}
```

回滚会做四件事：

```
截断步骤与产出（map 模式的 parts、串行模式的 notes 都截）
清掉过期素材（预取的事实清单；用户自己给的原文保留）
复位完成标志，删掉回滚点之后的检查点
把 extra 注入后续每一步和最终合成
```

**④ 然后继续：同一个 session_id 再调一次 /task**

```
第1次 1/5 → 第2次 2/5 → [回滚到 2] → 再调 3/5 → 4/5 → 5/5 完成
```

**回答只会越来越完整**：你补一句要求，它从断点继续，不用重头。

### 文件在哪

```
D:\<你的目录>\ce\.ce_runs\<会话>\step-NN.json    检查点（程序用）
%TEMP%\ce_logs\<会话>\<日期>.log                日志（人看，3 天自清）
```

## 附：命令执行怎么不炸

如果给 CE 接上执行能力（本项目里的 `owner_power` 插件）：

```
① 白名单    只有指定 QQ 号能触发；别人说什么都没用
② 危险拦截  format / diskpart / Remove-Item C:\ 这类直接拒
③ 熔断      同一命令 2 次失败 120 秒内 → 拒（真事：连试 20 次启动不存在的程序）
④ 审计      谁、什么时候、要干什么、结果，全部落日志
⑤ 不删文件  删除一律进回收站，不做永久删除
```

**原则：能由代码拦住的，绝不指望模型自觉。**

## 一句话总结

```
幻觉    → 真取料 + 命中集核对 + 数字一致 + 能算的不用它想
压榨    → 拆要求（不拆动作）+ 共享原文 + 分块产出 + 合并
回滚    → 每步留档 + 标红线索 + 人决定 + 带补充要求续跑
命令    → 白名单 + 危险拦截 + 熔断 + 审计 + 不永久删
```
