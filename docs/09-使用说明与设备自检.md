# 09 · 使用说明：先自检，再决定能不能并行

> 这份文档只有一个目的：**让你知道自己这台机器能喂多长，别喂爆。**
> 每台机器不一样，所以本项目不写死数字，只给测法和对照表。

---

## 一、三步上手

```powershell
# 第 1 步：自检（模型服务要先起着）
python default-workspace\agent-neurofusion\tools\probe.py

# 第 2 步：看它给的结论
#   单请求可容纳原文  约 8982 字
#   并行              不行 / 可以 N 路

# 第 3 步（可选）：觉得不合适就在 ce\config.json 里改数字
```

自检会写一份 **`ce\capacity.json`**，CE 启动时读它。
换机器、换模型、换量化 → **重跑一次自检**。

## 二、预设对照表（没跑自检时按这个估）

按 `单请求字数 ≈ (上下文 − 1200) × 1.5 × 0.85` 估的（中文字/token ≈ 1.5，再留 15% 余量）：

| 档位 | 上下文 n_ctx | 显存参考 | 单请求可喂 | 并行 | 适合 |
|---|---|---|---|---|---|
| 小 | 4 K | 4–6 GB | **约 3 600 字** | 1（串行） | 老显卡、7B 小模型 |
| 中 | 8 K | 8 GB | **约 8 900 字** | 1（串行） | 9B Q4，最常见的配置 |
| 大 | 16 K | 12–16 GB | **约 19 000 字** | 2 路 | 14B Q4 / 9B Q8 |
| 超大 | 32 K+ | 24 GB+ | **约 40 000 字** | 2–4 路 | 32B Q4 以上 |

**注意两件事：**

```
① 并行不看显存"总量"，看"余量"——模型占掉 7.4 GB，8 GB 卡就只剩 0.5 GB，
   再开一路 KV cache 必爆。自检就是替你算这个。
② 能跑 18000 不等于要塞两份 8000 并行：
   每路请求都要占一整份上下文，总占用超过上限一样炸。
```

## 三、CE 每次任务会先算总账

日志里会出现这样一行（`%TEMP%\ce_logs\<会话>\<日期>.log`）：

```
[11:53:22] 总账：正文 7697 字 → 分 1 段；并行 1 路（自检判定不能并行（服务只有 1 个 slot））
```

读法：

```
正文 7697 字   → 这次要处理的原文总长度
分 1 段        → 单请求能塞下，不用拆
并行 1 路      → 一块一块跑（功能不变，只是慢）
括号里         → 为什么不能并行（设备给的原因，不是随便写的）
```

正文超过单请求上限时会自动拆：

```
[总账] 正文 20000 字 → 分 3 段；并行 1 路
[块1/6] 原文 20000 字 → 分 3 段喂（单请求上限 8982 字）
```

**拆段是安全的**：每段各自提炼，最后合并；不会因为长文件只读前一半。

## 四、可调的四个数字（config.json）

```json
{
  "safe_source_chars": 8982,   // 单请求喂多少字；自检写进来，也可手改
  "max_parallel": 1,           // 能同时跑几路；1 = 一块一块来
  "source_total_chars": 60000, // 一份原文最多读多少字（超了才算"太长了"）
  "max_asks": 6,               // 最多拆成几块要求
}
```

**优先级**：`config.json` > `capacity.json` > 内置保守预设。
所以你**不必重跑自检**，改数字就行。

## 五、复杂指令：拆解与"一轮出结果"

用户视角只要一轮：**他发一句复杂指令，CE 内部连续跑完所有块，只交一份成品。**

`
POST /task {"task":"…","session_id":"x","stepwise":true,"auto":true}
`

uto:true 时，服务端在一次请求里循环执行所有块（拆解→取料→逐块产出→合并），
每块跑完就落盘，全部完成才返回成品。

### 拆解的兜底（保证不会拆成废块）

`
模型拆出来的东西过 _is_junk_ask：整句元词 / 等于原任务 / 自我指涉 / 扣词后实义字<3 → 丢
全被丢掉 → 退回「整篇当一个要求」，绝不空转
`

### 实测（9B Q4 / 8K / 串行）

`
输入  一句复杂指令（归拢→分类→计数→写简报）
结果  6 块，12.7 秒，一次请求返回，done=true，成品 452 字
日志  开始块1/6 … 开始块6/6 … 完成 6 块
`

### 不超时的前提

`
budget_sec      默认 180 秒（长任务请在 config.json 调大）
budget_calls    默认 30 次模型调用
块数            max_asks 默认 6（拆太多会变慢）
`

超了就按「超时 / 断线」那节处理：已完成的块都在，/last 取回，续跑。

## 四、超时 / 断线，内容会丢吗

**已完成的块不会丢，正在生成的那一块会丢。**

| 情况 | 结果 | 怎么取回 |
|---|---|---|
| 客户端超时 / 断线（分步模式） | 服务端继续跑完当前块；已完成的块都在 | GET /last?session=X 拿已有产出；再用同一 session 调 /task 接着走 |
| 客户端超时（单轮模式） | 答案已落盘 | GET /last?session=X |
| 模型调用中途被掐 | **这一块的半截文本会丢** | 前几块不受影响；日志里有「开始块 N/M」，能看出停在哪 |
| 进程被杀 / 断电 | 已落盘的块不丢（原子写） | 只能丢掉正在跑的那一块 |
| 预算 / 轮次用尽 | 不丢 | 返回「没做完」，/last 可取，链保留续跑 |

为什么正在跑的那块保不住：模型是流式吐字，半截文本没有合法落点。
所以 CE 的做法是**每块完成就落盘**，把损失限制在最大一块。

## 五、几个常问

**Q：不能并行是不是效果差？**
不是。**本地模型不要钱，只慢**。并联只影响速度，不影响结果——
只要一轮里能把活干完，串行完全可以。

**Q：文件很大怎么办，会不会爆？**
不会。正文超过单请求上限就**自动拆段**，每段单独喂，最后合起来。
`source_total_chars`（默认 6 万字）是"一份原文最多读多少"，超过才会截。

**Q：怎么强制串行 / 强制并行？**
`"max_parallel": 1` 强制串行；想要并行就填 >1，但**自检说不行时不要硬填**——
那不是限制，是显存余量算出来的结果。

**Q：跑一半发现太慢想停？**
有预算上限：`budget_sec`（默认 180 秒）、`budget_calls`（默认 30 次调用）。
超了就停，并把已完成的块保留在链里，下次同一个 `session_id` 能接着跑。

**Q：什么时候重跑自检？**
换模型、换量化、换显卡、改 `--n-parallel` 或 `-c` 参数之后。

## 六、一句话总结

```
自检测出上限 → 你填（或它自动填）→ 系统每次任务先算总账
→ 塞得下就一轮做完，塞不下就拆段，能并行才并行
→ 串行不丢人，跑得完才是目的
```

## 六、开盖即用清单（换个人能不能跑起来）

### 必须有

`
Python 3.9+            （纯标准库，不用 pip install 任何东西；3.7 以下不保证）
一个 OpenAI 兼容服务    （llama.cpp / Ollama / vLLM / LM Studio 都行）
                    接口形状：POST /v1/chat/completions
`

### 会自动适配

`
扩展字段     chat_template_kwargs / repeat_penalty 是 llama.cpp 的扩展。
            换到别的服务若被 400 拒绝，CE 会自动去掉这两个字段重试一次
            （日志会写「服务端不认扩展字段…去掉后重试」）
思考模式     disable_thinking=true（qwen3 必须）；别的模型不认就自动去掉
上下文上限   没跑 probe 时按保守预设 3000 字/串行；跑过就按实测值
无 NVIDIA 卡  probe 会说明「忽略并行，只看单请求字数」；CPU/AMD 照常可用，只是像串行
笔记库       没装 Obsidian 就跳过 [搜笔:]，不会报错
`

### 还依赖你的模型"肯配合"

`
① 肯按格式写工具标记：[查:xx] [读:path] [归:dir@1]
② 中文指令理解够用
③ 能拆成几块（拆不出来会退化成单块，不会崩）
`

**这些是模型能力，不是代码能保证的。** 实测只有 qwen3-9B 稳定通过；
7B 以下或指令跟随弱的模型，可能出现"不写标记、硬答"的情况——
这时的表现是**退化**（工具用不上、答案质量下降），不是崩溃。

### 没验证过的

`
Linux / macOS    代码无平台依赖，但没实跑
其他模型          7B / 14B / 32B / 非 qwen 系列
其他推理后端      Ollama / vLLM / LM Studio（回退逻辑写了，但没实跑）
`

## 七、上下文怎么控（每步都重建，不累积）

小模型爆上下文，多半不是单次输入太大，而是**把历史一路带着跑**。CE 的做法是三个入口各自控：

| 路径 | 每次调用带什么 | 会不会累积 |
|---|---|---|
| 分步（map） | system + 总任务 + **本段原文**（≤ 单请求字数）+ 这一个要求 | **不会**：每块每段都新建消息 |
| 分步（stepwise） | system + 前面各步的**摘要**（每条截断）+ 本步 + 本步工具结果（≤3000 字） | **不会**：完整历史从不进上下文 |
| 单轮 + 工具 | 最近若干轮对话 | 会累积，但**按字数预算裁剪**（不是按条数） |

### 工具说明书只在真的要调工具时才带

| 路径 | system 提示 | 为什么 |
|---|---|---|
| 分步（map） | **精简版 75 字**（角色 + 输出纪律） | 每一块只写成品，不调工具，带工具手册纯属浪费 |
| 分步合并 | 精简版 | 合并只是拼接/统稿 |
| 单轮 / stepwise | 完整版 615 字（工具清单 + 9 条规矩） | 这两条路真要调工具 |

工具结果进上下文也有上限：	ool_ctx_chars（默认 1200 字），超出截断。

实测同一任务（3 块、原文 2610 字、单请求上限 1800）：

`
        固定开销   段预算   调用次数   prompt tokens
改前      1058      742       13         10,882
改后       512     1288       10          6,047   ← 少 44%
`

**段预算要扣掉固定开销**：system 提示 + 总任务 + 本块要求 + 余量 约 1000–1100 字，
不扣的话"上限 1800"实际会发出去 2500 字，预算形同虚设。

实测（3 块 / 12 次调用，单请求上限 1800 字）：

`
段预算 742 = 上限 1800 - 固定 1058
块1 第1/4段: 上下文 1523 字 / 2 条消息
块1 第2/4段: 上下文 1523 字 / 2 条消息
块2 第1/4段: 上下文 1523 字 / 2 条消息      ← 换块了，字数没变
块3 第1/4段: 上下文 1523 字 / 2 条消息      ← 还是没变
`

每块都是 2 条消息（system + 本块），字数恒定在预算内 —— 这就是"不累积"的证据。

单轮路径的裁剪实测：

`
裁前 61 条 / 90,003 字
裁后  3 条 / 3,003 字（预算 3000）  ← system 保留，取最近的
`

**为什么按字数而不是按条数裁**：一条工具结果可能 1500 字，30 条就是 4.5 万字——
按条数裁看着"才 30 条"，实际早就爆了。这是踩过的坑。

## 八、检索：不用告诉它文件在哪

### 自动发现目录

不写 
ead_roots 时，CE 自己找这些地方（存在的才加）：

`
~/Desktop   ~/Documents   ~/Downloads   ~/OneDrive/Documents   ~/Documents/Obsidian   当前目录
`

想加自己的，config.json 里写 
ead_roots 即可，优先用你写的。

### 目录地图（代码生成，不经过模型）

任务里出现「有哪些 / 整理 / 归类 / 分类 / 清理 / 目录」时，**代码自动把目录地图塞进上下文**：

`
C:\Users\你\Documents\notes/
    项目计划.md
    周报2026.md
    日报.md
`

- 不指望模型主动 [地图:]（它连"自己不知道有哪些文件"都意识不到）
- 地图里的文件名同时登记为"命中"，否则接地守卫会把它当编造改掉（实测踩过）

### 文件名加权

问「日报」时，叫 日报.md 的文件排在前面；语义档和关键词档都加了这个权重。
否则会被"正文里提了一嘴日报"的大文件挤下去。

实测：

`
查「日报」     → 日报.md          （之前是 杂乱笔记.txt）
查「周报」     → 周报2026.md
查「项目计划」 → 项目计划.md
`

### 检索的限制（说清楚，不装）

`
关键词档   中文按二元切分，同义/拼音/近义查不到（"周报"查不到"每周总结"）
语义档     需要本地嵌入服务；短值查询（某个键值、端口号）召回差
多目录     每个目录都扫，目录特别多时建索引会慢
无权限目录  跳过，不报错
`
