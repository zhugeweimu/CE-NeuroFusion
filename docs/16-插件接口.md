# 16 · 插件接口（CE 的兼容边界）

> 原则：**CE 只做上下文压缩与取料；调度、定时、增量扫描、消息推送，全部归插件。**
> 这样 CE 保持单文件、无状态负担；插件随便换、随便写。

---

## 一、CE 对外只有一个稳定入口

```
POST /task
Content-Type: application/json
X-CE-Token: <可选，config.token 非空时必填>
```

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task` | string | ✅ | 要做什么（自然语言，含交付物要求） |
| `session_id` | string | — | 同一任务复用，可续跑/回滚；不同任务别共用 |
| `source` | string | — | **自己提供素材**（推荐插件用这个，CE 不扫目录） |
| `auto` | bool | — | true = 一次请求跑完所有块 |
| `stepwise` | bool | — | true = 分步（默认 map-reduce） |
| `save_to` | string | — | 结果写文件（必须在 `write_roots` 内） |
| `history` | list | — | 自己拼好的对话（少见） |
| `source_file` | string | — | 从 `read_roots` 里的文件读素材（需在白名单） |
| `iterate` | bool | — | 内置增量模式（**将迁出核心，建议插件自己扫**） |
| `max_rounds` | int | — | iterate 用，默认 3 |
| `since` | float | — | iterate 用，时间戳；不填用内置游标 |

### 返回

```json
{"ok": true, "answer": "...", "usage": {...}, "saved": "D:\\...\\x.md"}
```

失败时 HTTP 4xx/5xx + `{"error": "..."}`。

**插件只应依赖 `answer` 与 `error`。** 其余字段是给人看的。

## 二、其他端点（插件可选用）

| 端点 | 用途 |
|---|---|
| `GET /health` | 自检：`ok`、索引文件数、当前档位 |
| `GET /usage` | 累计调用与 token |
| `GET /runs?session=` | 运行记录（插件可展示进度） |
| `GET /logs?n=50` | 最近日志 |
| `GET /last?session=` | 上一次成品（客户端超时后取回） |
| `POST /rollback` | `{session_id, to_step, extra}` 回滚并注入补充要求 |
| `POST /rebuild` | 重建索引 |

## 三、插件该做什么、不该做什么

| 事情 | 归谁 | 原因 |
|---|---|---|
| 定时触发 | 插件 | CE 是被动服务，不该有定时器 |
| 扫新文件、维护游标 | 插件 | CE 的 `iterate` 只是兜底；游标属于调用方 |
| 分批（按字数） | 插件 | 分批预算取决于你的模型；插件最清楚 |
| 上下文压缩、拆要求、守卫 | CE | 这是 CE 的职责 |
| 结果落盘位置 | 插件 | CE 只认 `write_roots` 白名单 |
| 推送 QQ / 通知 | 插件 | CE 不发消息 |
| 重试与降级 | 插件 | CE 只做单次请求；重试策略属于调用方 |

## 四、参考插件：`ce_iterate`

```
astrbot_plugins/ce_iterate/
  ce_iterate_cli.py   扫描 + 分批 + 游标 + 调 CE（纯标准库，可独立跑）
  main.py             AstrBot 包装（命令 + 可选定时）
```

**独立跑（不用 AstrBot）：**

```bash
python ce_iterate_cli.py --roots "D:\笔记" --out "D:\笔记\增量整理" --task "整理成要点"
python ce_iterate_cli.py --roots "D:\笔记" --dry-run     # 只看会处理哪些文件
```

**AstrBot 里：**

```
环境变量：
  CE_ITER_ROOTS=D:\笔记
  CE_ITER_OUT=D:\笔记\增量整理
  CE_ITER_EVERY=1800          # 30 分钟自动跑一次；0=只手动
  CE_ITER_TASK=整理成要点清单
命令：
  /ce_iter 整理    /ce_iter 状态    /ce_iter 干跑
```

**游标文件**：`<roots[0]>/.ce_iterate_state.json`（原子写；删了就从近 7 天重新扫）。

## 五、写自己的插件时，照这四条走

```
① 只用 /task + source：不要依赖 CE 的 read_roots（那是给"现场取料"用的）
② session_id 要有区分度：插件名+批次+时间，避免不同任务互相踩链
③ 一次别超过 8000 字 source：那是单个请求的预算，超了 CE 会截断
④ 失败重试一次就够：CE 内部已有预算与熔断，插件再叠重试只会放大成本
```

### 最小可用示例

```python
import json, urllib.request

def ce(task, source, session="plugin-1"):
    req = urllib.request.Request(
        "http://127.0.0.1:8092/task",
        data=json.dumps({"task": task, "source": source, "session_id": session}).encode(),
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=300) as r:
        return json.loads(r.read().decode())["answer"]
```

## 六、边界与限制（写插件前必读）

```
· CE 不执行 shell、不删文件、不控制浏览器
· CE 不保证"每次都取对路径"，也不保证"绝不编造"——守卫是启发式
· 单请求有上下文上限（由 source_chars 决定），插件负责分批
· 无跨请求全局记忆：同 session_id 才有链，换 session 就是新任务
· 并发：CE 是 ThreadingHTTPServer，但模型服务才是瓶颈；插件别开太多并发
```
