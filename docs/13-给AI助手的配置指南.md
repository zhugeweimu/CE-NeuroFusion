# 13 · 给 AI 助手看的配置指南

> 你（读者是 AI 助手）要在一台陌生机器上把 CE 跑起来。
> **不要照抄任何硬编码数字，按下面的规则从实测结果推导。**
> 只改 `ce/config.json`，不要改 `ce/ce_tool.py`。

---

## 0. 先确认环境（缺哪个就别往下走）

```bash
python -V                      # 需要 3.9+；低了直接告知用户升级，别尝试兼容修改
python -c "import sys; print(sys.platform)"
```

CE 只用标准库，**不需要 pip install 任何东西**。

---

## 1. 模型服务（CE 不含模型）

CE 只说 OpenAI 兼容协议：`POST {llama_url}`。

```bash
# 起一个（任选）
llama-server -m 模型.gguf -c 8192 -ngl 99 --port 8080
ollama serve                                   # 之后 llama_url 用 :11434/v1/chat/completions
```

**验证命令（必须返回模型列表再继续）：**

```bash
curl -s http://127.0.0.1:8080/v1/models
```

失败就停下，把报错原文交给用户，**不要猜端口、不要改代码**。

---

## 2. 跑自检，拿实测值（这一步决定后面所有数字）

```bash
python tools/probe.py
```

它会写出 `ce/capacity.json`，关键字段：

| 字段 | 含义 | 用它来定 |
|---|---|---|
| `safe_source_chars` | 单次请求能喂多少字 | `config.source_chars` |
| `n_ctx` | 上下文长度 | 判断能否并行/分段粒度 |
| `slots` | 并发槽位 | `config.max_parallel`（必须 ≤ slots） |
| `vram_free_mib` | 显存余量 | 小于 512 就把并行设 1 |
| `chars_per_token` | 字↔token 比 | 估算成本，不用改配置 |

**没有 `nvidia-smi`（CPU 或 AMD）是正常的**：probe 会说明「忽略并行，只看单请求字数」，照它给的 `safe_source_chars` 走。

---

## 3. 推导配置（按规则算，不要抄例子）

复制模板：`cp ce/config.example.json ce/config.json`

必须填 / 建议改的键：

```jsonc
{
  "llama_url": "http://127.0.0.1:8080/v1/chat/completions", // 第 1 步验证过的地址
  "model": "模型名",            // 填 /v1/models 里真实存在的名字
  "source_chars": 0,            // = capacity.safe_source_chars
  "budget_sec": 0,              // ≥ 单块实测耗时 × 块数 × 2；拿不准就 900
  "max_parallel": 1,            // = min(capacity.slots, 4)；<=1 时就是串行
  "disable_thinking": true,     // qwen3 系列必须 true；别的模型保持 true 也无害
  "retry_times": 1,             // 用云端按 token 计费时改成 0
  "mem_write": "",              // 用户有记忆系统时填写入地址，没有就留空
  "memory_search_url": "",      // 同上，检索地址
  "read_roots": []              // 要查的目录；留空则自动发现常见目录
}
```

**推导规则（照做，不要凭经验拍数字）：**

```
source_chars   = capacity.safe_source_chars
max_parallel   = 1 如果 slots<=1 或 vram_free_mib<512；否则 min(slots, 4)
budget_sec     = 900 默认；若用户机器很慢（probe 里 chars_per_token 正常但实测慢），上不封顶可设 1800
retry_times    = 0 如果用户用云端 API 按 token 计费；本地模型保持 1
```

## 4. 启动与验收（四条都过才算配好）

```bash
python ce/ce_tool.py
```

```bash
# ① 活着
curl -s http://127.0.0.1:8092/health
# 期望：{"ok": true, ... "retrieval": "semantic|keyword|memory|none"}

# ② 真能答（会调一次模型）
curl -s -X POST http://127.0.0.1:8092/task \
  -H 'Content-Type: application/json' \
  -d '{"task":"只回四个字：配置完成","session_id":"verify"}'

# ③ 用量记账
curl -s http://127.0.0.1:8092/usage

# ④ 分步能跑（小任务）
curl -s -X POST http://127.0.0.1:8092/task \
  -H 'Content-Type: application/json' \
  -d '{"task":"列出 3 条让本地模型更稳的建议","session_id":"verify2","stepwise":true,"auto":true}'
```

**判定：**

```
① ok=true 且 retrieval 不是 none（若用户没配任何资料，none 也算正常）
② answer 非空
③ total.calls >= 1
④ progress.done = true 且 answer 里有 3 条
```

## 5. 出错时按这张表处理（不要改代码）

| 现象 | 先查 | 处理 |
|---|---|---|
| 任务返回「连不上模型服务」 | `curl {llama_url 的基址}/v1/models` | 模型服务没起或端口不对；改 `llama_url` |
| 返回 400 / unknown field | 日志里有「服务端不认扩展字段」 | 正常，CE 已自动去掉重试；反复失败就设 `disable_thinking: false` |
| 回答是空的 | 模型是不是思考型 | 设 `disable_thinking: true` |
| 很慢、像卡死 | `/logs?session=x` 看停在哪块 | 降 `source_chars`（如 ×0.6），或把 `auto` 改成分步调用 |
| 内容被截断 | `capacity.n_ctx` 太小 | 起模型时加 `-c 8192` 以上 |
| 检索说没资料 | `/health` 里 `retrieval` | `read_roots` 填目录，或 `retrieval` 设为 `keyword` |
| `[记:]` 说没接记忆系统 | `config.mem_write` | 填写入地址；没有记忆系统就保持留空 |

---

## 6. 明确禁止的动作

```
✗ 改 ce/ce_tool.py（改了就与发布版本不一致，问题无法复现）
✗ 为了让测试通过而放宽参数（如 budget_sec 调到 99999、max_parallel 调 8）
✗ 编造 llama_url / model 名（必须是 /v1/models 里真实存在的）
✗ 在没有 probe 结果时凭感觉填 source_chars
```

---

## 7. 交付给用户的汇报格式

```
模型       {model} @ {llama_url}
自检       n_ctx={n_ctx} slots={slots} 单请求={safe_source_chars} 字
配置       source_chars={..} max_parallel={..} budget_sec={..}
验收       /health ok  | 单轮 ok  | 分步 ok（{n} 块）
已知限制   {例如：CPU 推理，约 {x} 字/秒；未验证并发}
```

**不要写「已完全优化」「性能最佳」这类话**——你没有基准数据，写了就是编。
