# 14 · 一次任务到底怎么走（完整工作过程）

> 这篇是给"想知道它内部到底发生了什么"的人看的。
> 按时间顺序走一遍：从启动、配置、取料、生成、守卫、写入、回滚。

---

## 0. 启动

```
python ce/ce_tool.py
  ├─ 读 ce/config.json（没有就用默认值）
  ├─ 读 ce/capacity.json（probe 产出的实测值，可选）
  ├─ 建索引：扫 read_roots 下的 .md/.txt/.json/.py/.log
  │    单文件上限 512 KB，总文件数上限 index_max_files（默认 3000）
  │    跳过 index_skip_dirs（node_modules/.git/venv 等）
  ├─ 读 Obsidian 登记表（%APPDATA%\obsidian\obsidian.json，可选）
  └─ 起 HTTP 服务（默认 127.0.0.1:8092）
```

**启动日志会打印真实配置**，别靠猜：

```
CE 配置：model=… source_chars=… max_parallel=… 索引=87 个文件
```

---

## 1. 请求进来

```
POST /task
{
  "task":    "把她的桌面整理成三组并写日报",
  "session_id": "abc123",      // 同一任务多次请求要复用，链才接得上
  "auto":    false,            // true = 一次请求里跑完所有块
  "stepwise": false,           // true = 走分步（默认 map-reduce）
  "source":  ""                // 可选：自己提供素材，CE 就不再取料
}
```

其他端点：`/health`（自检）、`/usage`（用量）、`/runs`（运行记录）、
`/logs`（日志）、`/last`（上一份成品，客户端超时后用）、`/rebuild`（重建索引）、
`/rollback`（回滚某步）。

---

## 2. 意图识别：这句要不要动工具

```
need_tool(task) → "" | "查" | "读" | "归" | "记" | "搜笔" | "读笔" | "日" | "地图"
```

规则是"代码说了算"，不是模型说了算：

| 意图 | 触发条件 |
|---|---|
| 归 | 有「归拢/清点」；或（目录词 目录/文件夹/桌面/路径/盘符/反斜杠）**且**（清点词 列出/列一下/有哪些/有什么/多少个/统计） |
| 查 | 查一下 / 查查 / 搜一下 / 找一下 / 翻一下 |
| 读 | 读一下 / 打开这个文件 / 读这个文件 |
| 记 | 记 / 记一下 / 记住 |

**为什么要这么严**：`列出三条建议` 不是归拢。如果 "列出" 直接算意图，
普通写作任务会被拉去读目录，结果里冒出"没有这个目录"。

---

## 3. 参数抽取：不让模型抄路径

```
extract_arg("归", "归拢 D:\某目录")
  → 剥尾巴（里有什么 / 的文件 / 多少个 / 有多少 / 一下 / 看看）
  → 必须像目录（盘符 / 反斜杠 / 含目录词）
  → 不像目录就返回 "" —— 宁可不做，也不乱猜
```

**抽得出来就代码直接执行**，不问模型（模型会抄成占位词）。
抽不出来才让模型自己写 `[归:…]` 标记。

---

## 4. 取料：四个工具，全是代码

```
[归:目录@天数]   列最近 N 天变动过的文件（@0 = 全量）
                  N 天没变动 → 退回全量清单（最多 60 条），并注明"N 天无变动"
                  结果里的文件名会进 hits，供后面的"接地守卫"核对

[读:路径@段号]   读文件，分段（默认每段 1500 字）
                  路径必须在 read_roots 内，越界直接拒

[查:关键词]      先词法检索，semantic=true 时再走嵌入检索（可选）

[搜笔:词]        在 Obsidian 库内搜 .md/.txt        ┐ 只有装了 Obsidian
[读笔:路径@段]   读库内某篇                        │ 才生效
[日:内容]        追加到 日记/YYYY-MM-DD.md          │
[记:笔记.md|内容] 追加到指定笔记                    ┘

[地图:]          列出 read_roots 的结构（不是 Obsidian 库！）
```

**所有工具都是"执行 → 把结果回灌给模型"，不是让模型自己想象。**

---

## 5. 生成：单轮 / 分步 / 分块

```
run_task
 ├─ stepwise=true 且 plan=map  → run_mapreduce（默认）
 ├─ stepwise=true 且 plan=chain → run_stepwise
 └─ 否则 → 单轮：模型 + 最多 max_tool_rounds 轮工具循环
```

**map-reduce 怎么切**（这是"8K 干 32K"的核心）：

```
① 拆要求：模型把任务拆成几个"彼此独立的交付物"
② 取共享素材：source 没给 → 代码先 [归:][读:][查:] 取一份
③ 固化素材：第一块取到的 source 存进会话链，后面几块共用
④ 逐块生成：每块只带「总任务 + 共享素材 + 这一块的要求」
             按 source_chars 分段，**不累积历史**
⑤ 每块落盘：part、checkpoint、last-answer.txt
⑥ 合并：多块按标题拼接；太短才叫模型统稿
```

**段预算** = `source_chars − system − task − detail − 400`（约 400 字留给输出与工具结果）。

---

## 6. 守卫：抓"看起来合理"的谎

| 守卫 | 抓什么 | 抓不住什么 |
|---|---|---|
| 接地守卫 | 回答里的文件名必须在本轮 hits 里 | 理解错内容 |
| 声称守卫 | 说"我查了"但本轮零工具调用 | 查了但没看懂 |
| 数字守卫 | 同一"量名"跨步数值矛盾 | 算错 |
| 条目守卫 | 要求"5 条"只给 3 条 → 重写一次 | 内容质量 |

**全部是启发式。** 能拦的是"编文件名、前后矛盾、假装做过"，不是"想错了"。

---

## 7. 写入：三处，各有边界

```
① 记忆库（可选）   mem_write 为空 → 不写，[记:] 会如实说"没接记忆系统"
                    接了任意 HTTP 服务都行，不绑定任何实现
② Obsidian（可选） 只追加、不覆盖；路径锁在库内；拒绝 ..；单次 ≤2000 字
③ 运行记录           .ce_runs/<session>/step-NN.json、last-answer.txt
```

**通用版默认：记忆库空、Obsidian 自发现。** 不装 Obsidian、不接记忆系统，CE 照样能用。

---

## 8. 回滚

```
/rollback  {session_id, to_step}
  ├─ 截断会话链到第 N 步
  ├─ 保住这步的 source（后面的块继续用，不重复取料）
  ├─ 清掉过期素材（source_stale 标记）
  └─ 可以注入补充要求，再跑
```

链文件、last、笔记写入都是 **临时文件 + os.replace 原子替换**，断电不会写半个。

---

## 9. 配置从哪来（优先级）

```
source_chars:  config.safe_source_chars
             > capacity.safe_source_chars
             > config.source_chars
             > 3000

max_parallel:  config.max_parallel > capacity.max_parallel > 1
```

`capacity.json` 由 `tools/probe.py` 实测产出；**没有它也能跑**，只是用保守值。

---

## 10. 一句话总结

```
模型只做三件事：拆要求、写正文、写工具标记
其余全部由代码完成：取料、守卫、切块、落盘、回滚
```

**这就是它和"给 7B 写一段更长的提示词"最本质的区别。**

---

## 附：本地版与通用版的差别

| 项 | 通用版（发布） | 你本地 |
|---|---|---|
| `read_roots` | 空 → 用当前工作目录 | 你的几个目录 |
| `mem_write` | 空 → 不写记忆库 | 你的记忆服务地址 |
| Obsidian | 自动发现，没有就提示 | 你的库 |

**代码完全一样，差别只在 config.json —— 它不进仓库。**
